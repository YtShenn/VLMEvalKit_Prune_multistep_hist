# 多步 GUI 任务加速方法总结

本文档总结了当前对话中讨论过的、面向多步 GUI / AndroidControl / GUI Odyssey 类任务的 `image encode` 与 `prefill` 加速方法。

重点覆盖：

- 方法核心思想
- 是否需要训练
- 主要加速阶段
- 理论加速倍数
- 对精度的影响程度
- 是否适合“尽量无损”的目标

本文默认关注多步轨迹任务，其中：

- `当前截图` 更偏向精细定位与最终动作预测
- `历史截图` 更偏向状态补充与轨迹上下文

因此很多方法都建立在一个共同假设上：

- 当前截图与历史截图不应使用完全相同的 token 预算策略

## 一、统一记号

为了统一表达理论速度，使用如下符号：

- `P`：单张图片进入 LLM 前的 visual token 数
- `V`：一个样本中总 visual token 数
- `T`：文本 token 数
- `L`：LLM 总层数
- `l`：在第 `l` 层后把 visual token 从 `V` 压到 `K`
- `K`：LLM 中剩余的 visual token 数
- `E`：视觉编码器总层数
- `e`：视觉侧做 condensation / pruning 的层
- `r`：视觉侧保留比例，即 token 数从 `P` 压到 `rP`
- `H`：历史截图数量
- `m`：每张历史截图压缩后的等价 token 数
- `rho`：变化 patch 比例

常用理论上界公式：

- 视觉编码理论加速：
  `S_encode ~= 1 / ( e/E + (1-e/E) * r^2 )`
- LLM prefill 理论加速：
  `S_prefill ~= 1 / ( l/L + (1-l/L) * ((T+K)^2 / (T+V)^2) )`

这些数字主要用于分析上界，不等于真实端到端测得速度。

## 三、各方法详细说明

### 1. 轨迹感知的视觉增量缓存

#### 核心思想

相邻两步截图通常高度相似，因此不必每一步都完整重编码整张历史图或当前图，只需要对发生变化的区域重新编码，未变化区域直接复用之前的视觉特征。

#### 是否需要训练

- 可以完全不训练
- 也可以做成更强的学习版，但不是必须

#### 典型实现

- 对相邻截图做差分
- 找到变化 patch / tile
- 仅对变化区域重新跑视觉编码
- 未变化区域复用缓存特征
- 需要时加一个轻量后处理，修正边界误差

#### 理论加速倍数

若前 `e` 层仍全图处理，后续只处理变化区域，则：

- 二次近似：
  `S_encode ~= 1 / ( e/E + (1-e/E) * rho^2 )`

示例：

- `e/E = 1/4`
- `rho = 0.2`

则理论上界约：

- `3.57x`

更保守线性估计约：

- `2.50x`

#### 精度影响程度

- 预期：`低到中`

#### 原因

- 如果页面变化区域很集中，这个方法通常较稳
- 但如果变化检测漏掉了关键 UI 状态变化，就会直接伤害决策

#### 是否适合尽量无损

- `是，较适合`

这是所有讨论方法里，比较容易接近“低损甚至近似无损”的一类，尤其适合多步 GUI 轨迹任务。

### 2. 历史截图到紧凑状态表示

#### 核心思想

历史截图不再以完整 patch token 形式存在，而是压缩成少量 state token / memory token，再送入主 LLM。

#### 是否需要训练

- 原始设想更适合训练
- 也可以做启发式近似版本

#### 典型实现

- 每张历史截图先编码
- 再压成 `m` 个状态 token
- 当前截图保留较多 token
- 历史图只提供紧凑状态

#### 理论加速倍数

若有 `H` 张历史图，历史图从 `P` 压到 `m`：

`S_prefill ~= ((T + (H+1)P)^2) / ((T + P + Hm)^2)`

示例：

- `H=4`
- `P=256`
- `m=16`
- `T=128`

则理论 attention 上界约：

- `9.9x`

#### 精度影响程度

- 预期：`中到高`

#### 原因

- 历史图一旦从“完整视觉证据”变成“抽象状态”，精度就高度依赖压缩是否保留了正确的任务信息
- 若任务需要回溯细粒度历史视觉证据，这类方法容易伤精度

#### 是否适合尽量无损

- `不太适合严格无损`

除非压缩很弱、保留 token 足够多，否则通常不是“尽量无损”的首选。

### 3. 把 token condensation 前移到 vision encoder 内部

#### 核心思想

不要等 visual token 全部进入 LLM 后再剪，而是在 vision encoder 中间层就把低重要度 patch 合并掉。

#### 是否需要训练

- 可以训练
- 也可以做零训练启发式版本

#### 典型实现

- vision encoder 前几层正常跑
- 到第 `e` 层后，对 patch 打分
- 高分 patch 保留
- 低分 patch 合并成 super token
- 后续视觉层与主 LLM 只处理压缩后的 token 集

#### 理论加速倍数

视觉侧：

`S_encode ~= 1 / ( e/E + (1-e/E) * r^2 )`

示例：

- `E=24`
- `e=6`
- `r=1/4`

则理论上界约：

- `3.37x`

LLM prefill 侧若 token 从 `256 -> 64`，常见上界约：

- `~2.0x - 2.3x`

#### 精度影响程度

- 预期：`中`

#### 原因

- 当前图本身负责定位，如果压得太狠，容易损失 grounding 精度
- 但如果采用“前景保留、背景合并”的策略，伤害可控制

#### 是否适合尽量无损

- `可以，但必须非常保守`

如果只合并低价值背景区域，并严格保留高显著 patch，则有机会接近低损。

### 4. 跨 step 的多模态前缀增量缓存

#### 核心思想

轨迹中相邻 step 的 prompt 大量重叠，因此不需要每一步都从零 prefill，可以跨 step 复用多模态 prefix KV cache。

#### 是否需要训练

- 不需要

#### 理论加速倍数

若窗口中有 `H` 张历史图与 1 张当前图，理论上界接近：

- `H + 1`

示例：

- `H=4`

则 attention 主导下上界接近：

- `5x`

更保守估计约：

- `3.85x`

#### 精度影响程度

- 预期：`极低`

#### 原因

- 本质上不是改表示，而是复用计算结果
- 如果位置编码和缓存一致性处理正确，精度几乎不应明显变化

#### 是否适合尽量无损

- `是`

#### 备注

虽然这条线很适合无损加速，但用户已指出这条方向已有相关工作，因此不作为优先创新点。

### 5. 精度约束下的自适应 token 预算调度

#### 核心思想

为不同样本动态选择不同的 history 数量、keep ratio 与 prune layer，而不是固定预算。

#### 是否需要训练

- 通常需要训练、拟合或策略搜索

#### 理论加速倍数

例子中讨论的平均加速上界约：

- `2.46x`

#### 精度影响程度

- 预期：`低到中`

#### 原因

- 只要调度策略合理，通常可保持较稳的精度
- 但如果预算策略分错样本，会导致明显退化

#### 是否适合尽量无损

- `可以`

但它不属于当前优先考虑的“纯启发式、免训练”主线。

### 6. 历史截图 State Packet

#### 核心思想

历史截图不再整图输入，而是转成一个启发式构造的紧凑状态包，例如：

- 一张极小缩略图
- 动作邻域 ROI
- 变化区域 ROI
- OCR 提取的局部文本
- 历史动作文本

构造历史状态包：

1. `动作邻域 ROI`
   * 如果是 click / long_press，就以 `b_h` 为中心扩一个窗口
   * 如果是 swipe，就取起点、终点附近两个窗口
   * 如果是 type，就取输入框附近窗口
2. `变化区域 ROI`
   * 对 `I_h` 和 `I_{h+1}` 做差分
   * 二值化 + 膨胀 + 连通域筛选
   * 保留面积最大的前 `k` 个变化块
3. `文字状态`
   * 对动作邻域和变化区域做 OCR
   * 抽取少量高频、靠近 ROI 的文本串
   * 这部分直接作为文本历史状态输入，而不是视觉 token
4. `全局缩略图`

* 保留一张非常低分辨率的历史缩略图，只用于保留页面整体布局

最终每张历史图不再是“1 张完整图”，而是：

* 1 张超小缩略图
* 2 到 4 个 ROI crop
* 若干 OCR 文本片段
* 1 条历史动作文本

这就是一个 `state packet`。

论文上怎么讲：

* 不是“压缩历史图”
* 而是“把历史截图从原始感知证据转化为紧凑状态表示”
* 而且这个状态表示是 `action-conditioned` 和 `transition-aware` 的

为什么这条线强：

* 完全不需要训练
* 非常贴合 GUI / AndroidControl
* 和一般图片任务不一样，任务感知很强
* 很容易做强 baseline

#### 是否需要训练

- 不需要

#### 理论加速倍数

示例设定：

- 每张历史图原本 `P=256`
- 压成状态包后等价 `m=48`
- `H=4`
- 当前图保留 `256`
- `T=128`

则理论 prefill 上界约：

- `(128+1280)^2 / (128+448)^2 ≈ 5.98x`

#### 精度影响程度

- 预期：`中`

#### 原因

- 相比完整历史图，State Packet 会丢失一部分背景与细节
- 但比极端压缩的 state sketch 更稳，因为仍保留局部 ROI 和少量视觉证据

#### 是否适合尽量无损

- `不属于严格无损，但可做低损版本`

如果：

- 保留较大的动作邻域
- 保留最关键的变化区域
- 对 OCR / ROI 策略设置保守

则有机会做到“相对低损”。

### 7. 历史截图 State Sketch

#### 核心思想

把历史截图进一步转成极度抽象的状态草图，例如：

- 粗网格布局
- 变化区域标记
- 动作位置标记
- OCR 文本摘要
- 极小缩略图

对每张历史图生成一个 `state sketch`，包含：

* 页面粗布局网格
  * 例如 `4x4` 或 `6x6` 网格
  * 每个格子记录：是否发生变化、是否包含动作点、文字密度、边缘密度
* 动作轨迹标记
  * 在 sketch 上标记 click / swipe / type 的位置和类型
* 文字摘要
  * 把 ROI 邻域里的 OCR 文字拼成简短状态描述
* 可选的微缩图
  * 一张极小的 downsample 页面图，保留整体色块布局

#### 是否需要训练

- 不需要

#### 理论加速倍数

如果每张历史图最终只剩 `16 - 32` 个等价 token，则 4 张历史图对应的理论上界可以达到：

- `6x - 10x`

#### 精度影响程度

- 预期：`高`

#### 原因

- 这种方法压缩非常激进
- 很容易丢掉小图标、局部控件状态、细粒度视觉证据

#### 是否适合尽量无损

- `不适合`

更适合作为激进压缩版本或对照组，而非主打无损方案。

### 8. 当前截图零训练早期视觉凝聚

#### 核心思想

在 vision encoder 中层使用启发式评分，对当前图 patch 做：

- 前景 patch 保留
- 背景 patch 合并

核心思想：
不要等 visual token 进入 LLM 后再剪；在 vision encoder 中间层就用启发式规则决定哪些 patch 保留，哪些 patch 合并成 super token。

一个很合理的零训练实现是：

在 vision encoder 前 `e` 层后，得到中层 patch token map。然后对每个 patch 打一个启发式分数：

`score = w1 * temporal_change + w2 * action_proximity + w3 * OCR_density + w4 * edge_density + w5 * local_activation_norm + w6 * center_bias`

这些量都不需要训练：

* `temporal_change`
  当前图和上一步图对应区域差分强度
* `action_proximity`
  离上一动作位置有多近
* `OCR_density`
  patch 内文字框数量或面积
* `edge_density`
  patch 内边缘/连通域密度
* `local_activation_norm`
  vision encoder 中层 token 的范数或能量
* `center_bias`
  GUI 中心区域常常更重要，可作为极弱先验

然后做两步：

1. `keep`
   * 保留 top-k 高分 patch，原样进入后续视觉层
2. `merge`
   * 低分 patch 不直接丢掉，而是按空间邻域做 pooling / clustering
   * 每个邻域合成一个 background super token

也就是说，你不是“前景保留、背景删除”，而是：

* 前景保留细粒度
* 背景压成低分辨率摘要

#### 是否需要训练

- 不需要

#### 典型启发式分数

例如可结合：

- temporal change
- action proximity
- OCR density
- edge density
- activation norm
- center bias

#### 理论加速倍数

视觉编码上界：

- 常见约 `2x - 3.4x`

prefill 侧若视觉 token 明显下降：

- 常见约 `~2x`

#### 精度影响程度

- 预期：`中`

#### 原因

- 当前图负责最后一步定位，任何 aggressive condensation 都有可能损失精度
- 但如果仅对明显背景区做合并，通常可以把损失控制在较低水平

#### 是否适合尽量无损

- `可以，但必须极保守`

例如：

- 只合并低得分背景区域
- 保留高分 patch 与关键文字区域
- 设 fallback 机制

### 9. 历史强压缩 + 当前轻压缩的非对称策略

#### 核心思想

把历史图和当前图区别对待：

- 历史图：强压缩
- 当前图：轻压缩

从而同时降低 prefill 与 encode 成本。

#### 是否需要训练

- 不需要

#### 理论加速倍数

组合后理论上界通常在：

- `2x - 5x`

具体取决于历史图压缩强度与当前图保留比例。

#### 精度影响程度

- 预期：`中`

#### 原因

- 当前图通常还能保住较强定位能力
- 但历史图被强压缩后，若任务确实依赖历史细节，依然会损失精度

#### 是否适合尽量无损

- `一般`

如果目标是“尽量无损”，这条线应当把历史压缩控制得更温和。

## 四、如果目标是“尽量无损”，最推荐哪些方法

若优先目标是：

- 不训练
- 加速明显
- 精度尽量无损

则推荐优先级如下：

### 第一梯队

#### 1. 跨 step 多模态前缀增量缓存

- 理论加速：`3.8x - 5x`
- 精度影响：`极低`
- 备注：很适合无损，但创新性可能不足

#### 2. 轨迹感知视觉增量缓存

- 理论加速：`2.5x - 3.6x`
- 精度影响：`低到中`
- 备注：在多步 GUI 任务里，是最像“低损创新方案”的方向

### 第二梯队

#### 3. 当前截图零训练早期视觉凝聚（保守版）

- 理论加速：encode `2x - 3.4x`，prefill `~2x`
- 精度影响：`中`
- 备注：只适合非常保守地合并背景 token

#### 4. 历史截图 State Packet（保守版）

- 理论加速：`3x - 6x`
- 精度影响：`中`
- 备注：可做成低损版本，但不属于严格无损

### 不推荐作为“尽量无损”主线的方法

#### 5. 历史截图 State Sketch

- 理论加速：`6x - 10x`
- 精度影响：`高`
- 备注：压得太狠，不适合无损目标

#### 6. 激进的历史状态 token 压缩

- 理论加速：`4x - 10x`
- 精度影响：`中到高`
- 备注：更适合论文创新，不适合先追求稳定无损

## 五、最终建议

如果当前目标是：

- 先做一个尽量无损、免训练、能发论文的方向

那么最值得优先考虑的是：

### 方案 A：轨迹感知视觉增量缓存

理由：

- 不需要训练
- 非常符合多步 GUI 轨迹特征
- 理论加速明显
- 精度风险相对较低
- 更有创新空间

### 方案 B：保守版当前图早期视觉凝聚

理由：

- 可以同时打 image encode 和 prefill
- 只要严格保留高显著 patch，精度不一定掉很多

### 方案 C：保守版历史 State Packet

理由：

- 对历史图进行温和压缩
- 比 state sketch 风险小
- 可以作为“非对称 token budget”论文的一部分

如果对“尽量无损”的要求非常强，那么从这次对话中讨论的方法来看，最稳的结论是：

- **越接近“计算复用”的方法，越接近无损**
- **越接近“信息重表示/强压缩”的方法，越容易影响精度**

因此：

- 无损性最好：缓存复用类、增量编码类
- 创新性最强但风险更大：状态压缩类、强 condensation 类
